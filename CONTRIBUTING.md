# Участие в разработке

Спасибо за интерес к 1c-tj-toolkit. Проект находится на ранней стадии: небольшие,
проверяемые изменения с явно описанными ограничениями особенно полезны.

## Перед началом работы

- Проверьте существующие issues и pull requests.
- Для заметного изменения сначала создайте feature request и опишите задачу,
  ожидаемый результат и затрагиваемые контракты.
- Об уязвимостях сообщайте по [SECURITY.md](SECURITY.md), а не в публичном issue.

## Конфиденциальность

Не публикуйте реальные технологические журналы 1С, результаты анализа, PDF,
SQLite, JSON или CSV с рабочими данными. Также удаляйте имена пользователей,
серверов, информационных баз и организаций, IP-адреса, внутренние URL,
абсолютные пути, SQL с бизнес-данными, email, токены и пароли.

Тесты и примеры должны быть минимальными, синтетическими и воспроизводимыми.
Замена имён без удаления чувствительного содержимого не считается достаточной
анонимизацией.

## Локальная проверка

Основной анализатор использует Python 3.10+ и стандартную библиотеку:

```powershell
python -B -m unittest discover -s tools/one_c_tj_analyzer/tests -v
python -B tools/one_c_tj_analyzer/analyze_1c_tj.py --version
python -B tools/one_c_tj_analyzer/derive_slices.py --list-slices
```

Для PDF установите закреплённые тестовые зависимости, затем выполните:

```powershell
python -m pip install -r requirements-report-test.txt
python -B -m unittest discover -s tools/one_c_tj_report/tests -v
```

Укажите в pull request точные команды, версии Python, результат и пропущенные
проверки. Успех на синтетических данных не следует называть производственной
валидацией или проверкой больших реальных журналов.

## Требования к изменениям

- Сохраняйте детерминированность результатов и явное происхождение показателей.
- Не смешивайте изменение алгоритма, обновление fixture и переработку
  документации без необходимости.
- При изменении JSON/CSV/SQLite-контракта обновляйте версию, документацию и
  регрессионные тесты.
- Не ослабляйте строгую проверку версий переименованием версии входного файла.
- Не добавляйте сетевую отправку журналов или результатов без отдельного,
  явно обсуждённого решения.
- Сохраняйте границу между расчётом аналитики и отображением PDF.
- Описывайте ограничения и непроверенные предположения рядом с результатом.

## Pull request

В pull request укажите:

- цель и краткое описание решения;
- связанный issue, если он есть;
- затронутые форматы и совместимость;
- выполненные тесты и их точный результат;
- оставшиеся ограничения;
- происхождение и лицензию новых сторонних материалов.

Отправляя изменение, вы соглашаетесь распространять свой вклад в основной код
и документацию по [MIT License](LICENSE). Сторонние материалы должны иметь
совместимую лицензию и быть отражены в
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Liberation Sans остаётся под
отдельной SIL Open Font License 1.1.
